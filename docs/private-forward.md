# 私聊转发到论坛话题

这个功能默认关闭。只有当前账号在设置里明确打开，并选中一个自己能创建话题、也能发言的论坛超级群之后，新到达的一对一私聊才会被转发。不会回填打开聊天时加载的历史。

群成员可以阅读被转发的私聊。这是设置页和开启确认里写明的行为。

## 会转发什么

- 功能打开之后新到达的一对一私聊。
- 文字、图片、视频、文件、语音、贴纸。视频包含普通视频、圆形视频和 GIF。
- 同一组相册会合成一次发送。
- 可选：自己发出的私聊、编辑/删除提示、复制发送、双向回复、其他管理员代回复。

## 不会转发什么

- 群、频道、收藏夹、Telegram 服务号（编号能被 1000 整除的系统账号，包括 777000 登录码）、验证码会话和 Replies。
- 机器人在「忽略机器人」打开时的消息。机器人发出的纯数字或带有 login code / 验证码字样的消息，即使关掉忽略机器人也不会转发。
- 阅后即焚、开启禁止转发、或媒体本身不允许转发的内容。复制模式也不会拿这些内容去绕过限制。
- 投票、名片、位置、发票、游戏和动态。带网页预览的普通文字仍按文字转发。
- 关闭「每个联系人自动创建一个话题」后，转发会停住，不会把不同联系人堆进同一个话题。

## 话题、重启和失败

- 每个私聊对应目标论坛里的一个话题。映射按账号分开保存在 `tdata/ayu_private_forward_<账号>.json`，里面没有消息正文。
- 联系人改名后会尝试更新话题标题。
- 话题被删或关闭时会重新建一次再发。权限丢失会暂停，并记在「最近错误」里。
- 发送排队，大约每 400 毫秒一条。遇到 `FLOOD_WAIT` 会按服务器给的秒数重试同一次请求，不另起一条。
- 本功能自己发出的消息带有一个不可见标记，并记下消息 id。重启后这些 id 还在，所以不会把刚转发的内容再发回私聊。
- 程序在写入映射之前崩溃时，这一条可能丢掉，以避免重发或打环。
- 桌面端关闭期间，手机上自己发出的消息不会补转发。

## 双向回复

默认关闭。打开之后，只有当前登录账号在对应话题里新写的消息会发回那个私聊。转发功能自己贴进去的消息不会回弹。

其他成员的消息只留在群里。气泡上可能出现「仅群内」「发送中」「已发回」或「发回失败」。只有服务器接受之后才会显示「已发回」。

回复某一条已经转发的消息时，会尽量在私聊里回复到原来的那条。

「允许其他管理员代我回复」另外默认关闭。打开前有确认。真正发送前会调用 `channels.getParticipant` 核对对方现在仍是管理员，不是机器人，并且这条消息不是匿名身份。结果会缓存约 15 秒，避免连发时打爆接口。

## 复制模式的限制

打开「隐藏转发来源」后，用普通发送代替转发头，并在正文前加上「名字 HH:mm」。文字格式、链接和自定义表情不会保留。图片、视频、文件、语音和贴纸仍引用原来的媒体；如果服务器拒绝这次引用，日志里会留下错误码，不会提前显示成功。

## 日志

「今日已转发」只统计服务器已经接受的转发条数。「最近错误」和「查看日志」只记录动作、账号内的 peer id、消息 id 和错误码，不记录正文。

## 手动测试清单

不要用真实联系人做第一次试验。用另一个自己的测试号，和一个只有自己是管理员的论坛群。

1. 全新安装或清空该账号的 `ayu_private_forward_*.json` 后，设置里总开关是关的，双向回复和其他管理员代回复也是关的。不打开时，新私聊不会出现在任何群里。
2. 打开总开关时能看到群成员可读的警告。取消后开关回到关。不选论坛群时状态是「未选择目标群」，仍然不转发。
3. 选择器里只有已开启话题、且当前账号能创建话题并发言的超级群。普通群、频道和没有权限的论坛不会出现，强行指定的坏目标会被拒绝。
4. 打开后让测试号发来一条新文字。论坛里出现该联系人的话题，历史里更早的消息不会被补发。再发一次同一条不会重复。
5. 群消息、频道消息、收藏夹、777000 的登录码不会出现在论坛里。
6. 打开禁止转发或阅后即焚后，内容不会被转发，日志里能看到跳过，而不是成功。
7. 一次发三张图，论坛里是一组相册，不是三张互不相干的图。
8. 把目标群的发言权限拿掉。状态变为暂停，最近错误不是「无」。恢复权限并改一下设置后，新消息可以继续。
9. 关掉客户端再打开。已有话题继续用，不会新建第二个，也不会把旧历史再发一遍。
10. 打开双向回复。在话题里新写一句，私聊里出现这句话，气泡先是「发送中」，服务器接受后才变成「已发回」。失败时是「发回失败」加上错误码。
11. 用另一个普通成员在话题里发消息，私聊不会收到，气泡是「仅群内」。
12. 打开「其他管理员代我回复」前能看到确认。匿名管理员和机器人的消息不会发回私聊。
13. 把测试号加入排除列表或静音后再发消息，不会转发。机器人在「忽略机器人」打开时也不会转发。
14. 换一个 Telegram 账号。前一个账号的话题映射和计数不会出现在这个账号里。

## 编译检查

路由、去重、回环、账号隔离、限流和话题创建竞态有独立测试，不需要登录：

```bash
g++ -std=c++20 -I Telegram/SourceFiles \
  Telegram/SourceFiles/ayu/features/private_forward/forward_policy.cpp \
  Telegram/SourceFiles/ayu/features/private_forward/forward_policy_test.cpp \
  -o /tmp/private_forward_test
/tmp/private_forward_test
```

这次环境里的结果是 `ok`。完整的 Windows 客户端没有在这里编译。

## 频道转发

频道转发和上面的私聊转发是分开的。私聊转话题、双向回复都还在，没有改掉。

频道转发默认关闭。要先打开总开关，再为每一条规则单独打开。来源只能是当前账号能看到的广播频道，目标只能是当前账号能发言的群或频道。来源和目标不能相同。论坛群必须自己选定一个话题，没有话题列表时不会偷偷发到「常规」。

只转发规则启用之后、服务器时间不早于启用时刻的新消息。不扫描历史，也不补发。默认使用 Telegram 原来的转发，保留来源信息。禁止转发和阅后即焚的内容不会发。

一条消息可以按多条规则发到不同目标。本功能发出的消息会记下目标里的消息 id，以及来源消息 id。之后这些副本再出现在另一个来源频道里，不会被继续转发，重启后也一样。权限没了、来源不可用或话题没了，这条规则会暂停并记在日志里，不会一直重试。`FLOOD_WAIT` 仍和私聊转发共用同一个发送队列，按服务器给的时间重试。

频道转发是单向的。目标群或频道里的回复，以及回复到这些转发消息上的内容，不会触发私聊双向回传。

规则保存在 `tdata/ayu_channel_forward_<账号>.json`，按账号分开，里面没有消息正文。今日条数只统计服务器已经接受的频道转发。

手动检查时用自己的测试频道和空群，不要对真人开启规则：

1. 总开关和每一条规则默认都是关的。不打开时，频道新消息不会被转发。
2. 选择器里来源只有广播频道，目标只有能发言的群或频道。同一个对话不能同时当来源和目标。
3. 目标是论坛群时，不选话题就保存不了。话题列表是空的时候会提示先打开那个群，而不是直接发出去。
4. 打开规则之后的新频道消息会出现在目标里，并带有原来的转发来源。更早的消息不会补上。
5. 把同一条消息再从目标频道转回另一个来源时，不会循环转发。
6. 目标里回复这条转发，私聊不会收到。
7. 关掉目标的发言权限后，规则暂停，日志里有错误码，不会显示成已转发。
8. 换一个账号，看不到上一个账号的规则。

频道规则的自动化测试：

```bash
g++ -std=c++20 -I Telegram/SourceFiles \
  Telegram/SourceFiles/ayu/features/private_forward/channel_rules.cpp \
  Telegram/SourceFiles/ayu/features/private_forward/channel_rules_test.cpp \
  -o /tmp/channel_rules_test
/tmp/channel_rules_test
```

这次结果是 `ok`。Windows 便携包还没有构建，Actions 里的 “Windows portable” 仍要手动运行，步骤没有变，也不需要新的密钥。
